**Ключевые выводы:**

- Жёсткие ссылки и исходный файл имеют **один inode** и счётчик ссылок

- Мягкие ссылки зависят от имени целевого файла и ломаются при его переименовании или удалении
    
- Копия — полностью независимый файл с собственным inode и содержимым
    
- Жёсткие ссылки нельзя создавать на директории и на файлы в других файловых системах

## 1. Inodes — фундаментальное понятие файловой системы

**Inode** (index node) — это структура данных в файловой системе Linux, которая хранит метаинформацию о файле или директории, но **не содержит имя файла и его содержимое**.

### 1.1. Что хранится в inode

- Тип файла (обычный, директория, ссылка и т.д.)
    
- Права доступа (rwx)
    
- UID владельца и GID группы
    
- Размер файла
    
- Временные метки (создание, модификация, доступ)
    
- Счётчик жёстких ссылок
    
- Указатели на блоки данных на диске
    

### 1.2. Просмотр inode номеров

```bash
ls -li                # показать inode номера (ключ -i)
```

_Пример вывода:_

> 123456 -rw-r--r-- 1 itguy itguy 1024 Mar 26 10:00 main.config.file
> 123456 -rw-r--r-- 1 itguy itguy 1024 Mar 26 10:00 hardlink2config
> 789012 lrwxrwxrwx 1 itguy itguy   15 Mar 26 10:00 softlink2config -> main.config.file

### 1.3. Inodes и команда `df -i`

```bash
df -i /              # просмотр использования inodes на корневом разделе
```

Вывод показывает:

- **IUsed** — количество использованных inodes
    
- **IFree** — количество свободных inodes
    
- **IUse%** — процент использованных inodes
    

_Важно:_ файловая система может заполниться не только по месту, но и по количеству inodes. В этом случае создать новый файл будет невозможно, даже если свободное место есть.

## 2. Жёсткие ссылки (hard links)

Жёсткая ссылка — это **дополнительное имя файла**, указывающее на тот же inode, что и исходный файл.

### 2.1. Создание жёсткой ссылки

```bash
ln source_file hardlink_name
```

### 2.2. Характеристики жёстких ссылок

|Свойство|Описание|
|---|---|
|Один inode|Исходный файл и жёсткая ссылка имеют **одинаковый** номер inode|
|Счётчик ссылок|Каждая новая жёсткая ссылка увеличивает счётчик ссылок в inode|
|Независимость от имени|После переименования исходного файла жёсткая ссылка продолжает работать|
|Независимость от удаления|После удаления исходного файла жёсткая ссылка сохраняет данные (пока счётчик ссылок > 0)|
|Ограничения|Нельзя создать на разные файловые системы (разные разделы)|

### 2.3. Пример

```bash
echo "main config data" > main.config.file
ln main.config.file hardlink2config
ls -li
```

> # 123456 -rw-r--r-- 2 itguy itguy 20 ... main.config.file
> # 123456 -rw-r--r-- 2 itguy itguy 20 ... hardlink2config

Обратите внимание на вторую колонку (`2`) — это счётчик жёстких ссылок.

## 3. Мягкие (символические) ссылки — soft links

Символическая ссылка — это **отдельный файл**, который содержит путь к целевому файлу.

### 3.1. Создание мягкой ссылки

```bash
ln -s source_file softlink_name
```

### 3.2. Характеристики мягких ссылок

|Свойство|Описание|
|---|---|
|Разный inode|Ссылка и целевой файл имеют **разные** номера inode|
|Хранит путь|Содержит строку с путём к целевому файлу|
|Зависимость от имени|При переименовании целевого файла ссылка **ломается**|
|Зависимость от удаления|При удалении целевого файла ссылка **ломается**|
|Гибкость|Может указывать на файлы на других файловых системах|

### 3.3. Отображение в `ls -l`

> lrwxrwxrwx 1 itguy itguy 15 Mar 26 10:00 softlink2config -> main.config.file

- Первый символ `l` — тип файла (link)
    
- Права `rwxrwxrwx` — права самой ссылки (фактические права определяются целевым файлом)
    
- Стрелка `->` показывает, на какой файл ссылается
    

### 3.4. Сломанная ссылка (dangling link)

Если целевой файл удалён или переименован, ссылка становится нерабочей и подсвечивается красным цветом:

> lrwxrwxrwx 1 itguy itguy 15 Mar 26 10:00 softlink2config -> main.config.file (broken)

## 4. Сравнение жёстких и мягких ссылок

|Характеристика|Жёсткая ссылка (hard link)|Мягкая ссылка (soft link)|
|---|---|---|
|Создание|`ln source target`|`ln -s source target`|
|Inode|Одинаковый с исходным|Разный с исходным|
|После удаления исходного|Данные сохраняются|Ссылка ломается|
|После переименования исходного|Работает|Ломается|
|Может указывать на директорию|Нет|Да|
|Может работать между файловыми системами|Нет|Да|
|Размер|Размер исходного файла|Длина пути (несколько байт)|
|Отображение в `ls -l`|Обычный файл|`l` в начале, `->`|

## 5. Копия vs ссылки

Копия файла — это **полностью независимый файл** с собственным inode и содержимым.

### 5.1. Создание копии

```lua
cp main.config.file copyof.config
```

### 5.2. Поведение при изменении исходного файла

```bash
echo "new line" >> main.config.file   # добавить строку
ls -li
```

> # main.config.file   — размер увеличился
> # hardlink2config    — размер увеличился (тот же inode)
> # softlink2config    — размер не изменился (ссылка), но при чтении покажет новые данные
> # copyof.config      — размер остался прежним

|Объект|Реакция на изменение исходного файла|
|---|---|
|Жёсткая ссылка|Изменяется (общий inode)|
|Мягкая ссылка|Изменяется (читает исходный файл)|
|Копия|**Не изменяется** (независимый файл)|

## 7. Управление ссылками

### 7.1. Просмотр счётчика ссылок

```bash
ls -l
```

> # -rw-r--r-- 2 itguy itguy ...   (вторая колонка — количество жёстких ссылок)

### 7.2. Поиск всех жёстких ссылок на файл

```1c
find / -inum 123456 2>/dev/null   # поиск по номеру inode
```

### 7.3. Удаление ссылок

```bash
rm hardlink2config       # удаляет жёсткую ссылку, уменьшает счётчик
rm softlink2config       # удаляет символическую ссылку (целевой файл не трогает)
```

## 8. Практические примеры

### 8.1. Создание файла и ссылок

```bash
# Создать файл с содержимым
echo "Important configuration" > main.config
```

### 8.2. Эксперимент с переименованием

```bash
mv main.config renamed.config
cat hardlink          # работает
cat softlink          # ошибка: No such file or directory
cat renamed.config    # работает
```

### 8.3. Эксперимент с удалением

```bash
rm renamed.config
cat hardlink          # работает (данные сохранены)
cat softlink          # ошибка: broken link
```

### 8.4. Создание жёсткой ссылки на директорию (нельзя)

```bash
ln /home /home_link
```

> # ln: /home: hard link not allowed for directory

### 8.5. Создание мягкой ссылки на директорию

```bash
ln -s /home home_link
ls -l home_link
```

> # lrwxrwxrwx ... home_link -> /home
