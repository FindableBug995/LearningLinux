
В этом уроке рассмотрены основные возможности команды `usermod` для изменения параметров существующих пользователей:

|Действие|Команда|
|---|---|
|Блокировка пользователя|`sudo usermod -L username`|
|Разблокировка|`sudo usermod -U username`|
|Изменить домашний каталог|`sudo usermod -d /path username`|
|Изменить домашний каталог с перемещением содержимого|`sudo usermod -m -d /path username`|
|Изменить оболочку|`sudo usermod -s /bin/bash username`|
|Изменить основную группу|`sudo usermod -g groupname username`|
|Добавить в дополнительные группы|`sudo usermod -a -G group1,group2 username`|
|Изменить логин|`sudo usermod -l newname oldname`|
|Установить срок действия учётной записи|`sudo usermod -e 2025-12-31 username`|

**Ключевые понятия:**

- Блокировка добавляет символ `!` в начало хэша пароля в `/etc/shadow`
    
- Команды `useradd` и `usermod` используют одинаковый набор ключей
    
- Прямое редактирование файлов `/etc/passwd`, `/etc/shadow`, `/etc/group` возможно, но опасно и не рекомендуется
    
- При добавлении в дополнительные группы обязателен ключ `-a`, иначе существующие членства будут удалены

## 1. Введение в `usermod`

Команда **`usermod`** (сокращение от "user modify") используется для изменения параметров существующих учётных записей пользователей. Она имеет практически тот же набор ключей, что и **`useradd`**, что логично: если параметр можно задать при создании, его же можно и изменить впоследствии.

### 1.1. Базовый синтаксис

```bash
sudo usermod [ключи] username
```

## 2. Блокировка и разблокировка пользователя

### 2.1. Блокировка — `-L` (Lock)

```bash
sudo usermod -L username
```

- Запрещает вход пользователя в систему
    
- Пользователь при попытке входа получает сообщение об ошибке авторизации (без указания причины)
    

### 2.2. Разблокировка — `-U` (Unlock)

```bash
sudo usermod -U username
```

- Восстанавливает возможность входа
    

### 2.3. Механизм блокировки

Блокировка реализуется добавлением символа `!` (восклицательный знак) в начало хэша пароля в файле `/etc/shadow`. При разблокировке этот символ удаляется.

_Проверка:_

```bash
sudo cat /etc/shadow | grep username
```

- Заблокированный: `username:!$6$...`
    
- Разблокированный: `username:$6$...`

## 3. Изменение домашнего каталога

### 3.1. Изменение пути — `-d` (home directory)

```bash
sudo usermod -d /new/home/path username
```

- Изменяет запись о домашнем каталоге в файле `/etc/passwd`
    
- **Не создаёт** новую папку автоматически
    

### 3.2. Изменение пути с созданием папки — `-m` (move)

```bash
sudo usermod -m -d /new/home/path username
```

- Ключ `-m` (move) перемещает содержимое старого домашнего каталога в новый
    
- Новый каталог создаётся автоматически
    

### 3.3. Пример: добавление домашнего каталога пользователю без него

```bash
sudo usermod -d /home/officemanager officemanager
sudo mkdir /home/officemanager
sudo chown officemanager:officemanager /home/officemanager
```

_Примечание:_ создание папки в `/home` требует прав root, поэтому используется **`sudo mkdir`**.

## 4. Изменение командной оболочки — `-s` (shell)

Командная оболочка (shell) определяет среду, в которой пользователь работает после входа.

### 4.1. Синтаксис

```bash
sudo usermod -s /path/to/shell username
```

### 4.2. Пример: смена оболочки на `/bin/bash`

`**sudo usermod -s /bin/bash officemanager sudo usermod -s /bin/bash smileygirl**`

### 4.3. Распространённые оболочки

|Оболочка|Описание|
|---|---|
|`/bin/bash`|Bourne Again Shell — наиболее распространённая, богатая функциональностью|
|`/bin/sh`|Bourne Shell — более простая, может быть ссылкой на bash в совместимом режиме|
|`/bin/zsh`|Z Shell — расширенная альтернатива bash|
|`/usr/sbin/nologin`|Запрещает вход (используется для системных пользователей)|
|`/bin/false`|Немедленно завершает сессию (также запрещает вход)|

### 4.4. Проверка изменений

```bash
cat /etc/passwd | grep username
```

В последнем поле строки будет указана новая оболочка.

## 5. Другие полезные ключи `usermod`

|Ключ|Описание|Пример|
|---|---|---|
|`-g <группа>`|Изменить **основную** группу|`sudo usermod -g developers username`|
|`-G <группы>`|Задать **дополнительные** группы (список через запятую)|`sudo usermod -G sudo,www-data username`|
|`-a -G <группы>`|Добавить в дополнительные группы (без удаления существующих)|`sudo usermod -a -G docker username`|
|`-u <UID>`|Изменить UID пользователя|`sudo usermod -u 2000 username`|
|`-l <новый_логин>`|Изменить логин пользователя|`sudo usermod -l newname oldname`|
|`-e <YYYY-MM-DD>`|Установить дату истечения учётной записи|`sudo usermod -e 2025-12-31 username`|

## 6. Прямое редактирование файлов пользователей (не рекомендуется)

Технически информацию о пользователях можно изменять, редактируя файлы:

- `/etc/passwd` — основная информация
    
- `/etc/shadow` — хэши паролей
    
- `/etc/group` — информация о группах
    

**Почему этого лучше не делать:**

- Нет проверок на корректность формата
    
- Ошибка может привести к невозможности входа в систему
    
- Можно случайно удалить или повредить системные учётные записи
    
- Специализированные команды (`usermod`, `useradd`, `passwd`) выполняют необходимые проверки и обеспечивают целостность данных

## 7. Практические примеры

### 7.1. Блокировка и разблокировка пользователя

```bash
sudo usermod -L outgoinghr   # заблокировать
sudo usermod -U outgoinghr   # разблокировать
```

### 7.2. Смена домашнего каталога

```bash
sudo usermod -d /home/newoffice officemanager
sudo mkdir /home/newoffice
sudo chown officemanager:officemanager /home/newoffice
```

### 7.3. Смена оболочки

```bash
sudo usermod -s /bin/bash smileygirl
```

### 7.4. Добавление пользователя в группу sudo

```bash
sudo usermod -a -G sudo officemanager
```

Ключ `-a` (append) обязателен, чтобы не удалить пользователя из других дополнительных групп.

### 7.5. Изменение логина

```bash
sudo usermod -l new_username old_username
```
