|Тема|Команды / Понятия|
|---|---|
|SUID|`chmod u+s`, `chmod u-s`|
|SGID|`chmod g+s`, `chmod g-s`|
|Sticky Bit|`chmod +t`, `chmod -t`|
|Отображение в `ls -l`|`s`/`S` (SUID), `s`/`S` (SGID), `t`/`T` (Sticky)|
|Права по умолчанию|`umask` (просмотр и установка)|
|Формула прав по умолчанию|`666 - umask` для файлов, `777 - umask` для директорий|

**Ключевые понятия:**

- **SUID** — позволяет выполнять файл с правами владельца
    
- **SGID** — для файлов: выполнение с правами группы; для директорий: наследование группы
    
- **Sticky Bit** — защита от удаления чужих файлов в общей директории
    
- **umask** — маска, определяющая права для вновь создаваемых файлов

## 1. Подготовка тестовой среды

Перед рассмотрением специальных битов необходимо очистить рабочую директорию и создать тестовые файлы.

```bash
rm -r *                 # удалить все файлы и папки в текущей директории
touch public_executable_file private_executable_file
```

## 2. Специальные биты

Помимо стандартных прав `rwx`, в Linux существуют три специальных бита, которые изменяют поведение системы при работе с файлами и директориями.

1. **SUID (Set User ID)** — при запуске файла временно заменяет реального пользователя на владельца файла, что позволяет обычным пользователям выполнять привилегированные действия (например, `passwd` меняет файл `/etc/shadow` от имени root).
    
2. **SGID (Set Group ID)** — при запуске файла подменяет группу пользователя на группу файла (для файлов), а для каталогов — заставляет все новые объекты наследовать группу родительского каталога, что нужно для организации общего доступа к файлам внутри одной группы.
    
3. **Sticky bit** — ограничивает удаление файлов в общем каталоге так, что удалить или переименовать файл может только его владелец, root или владелец каталога, что используется для защиты чужих файлов в общедоступных местах (например, `/tmp`).

### 2.1. SUID (Set User ID)

**Назначение:** при запуске исполняемого файла процесс получает права **владельца** файла, а не пользователя, который его запустил.

#### 2.1.1. Установка и снятие SUID

```bash
chmod u+s filename      # установить SUID
chmod u-s filename      # снять SUID
```

#### 2.1.2. Отображение в `ls -l`

|Отображение|Значение|
|---|---|
|`-rws------`|SUID установлен, право на исполнение (`x`) есть|
|`-rwS------`|SUID установлен, права на исполнение **нет** (бессмысленная комбинация)|

#### 2.1.3. Пример

```bash
# Дать владельцу право на исполнение
chmod u+x public_executable_file
```

#### 2.1.4. Поведение

- **public_executable_file**: SUID + `x` → любой пользователь при запуске получает права владельца (`itguy`)
    
- **private_executable_file**: SUID без `x` → файл нельзя запустить, SUID не имеет эффекта
    

#### 2.1.5. Важное ограничение

SUID **не работает** на shell-скриптах (bash, python и т.д.) из соображений безопасности. Работает только с бинарными файлами.

#### 2.1.6. Примеры системных файлов с SUID

```bash
ls -l /bin/passwd /bin/ping /bin/su
# -rwsr-xr-x 1 root root ... /bin/passwd
# -rwsr-xr-x 1 root root ... /bin/ping
# -rwsr-xr-x 1 root root ... /bin/su
```

Эти файлы имеют владельца `root` и установленный SUID, поэтому любой пользователь может запустить `passwd` (для смены своего пароля) или `ping` с правами root.

​​​​​​​### 2.2. SGID (Set Group ID)

**Назначение:** изменяет поведение в зависимости от типа объекта:

- Для **исполняемых файлов**: процесс получает права **группы-владельца** файла
    
- Для **директорий**: новые файлы и папки, создаваемые внутри, наследуют группу родительской директории (вместо группы создателя)
    

#### 2.2.1. Установка и снятие SGID

```bash
chmod g+s filename      # установить SGID
chmod g-s filename      # снять SGID
```

#### 2.2.2. Подготовка примера

```bash
# Дать группе право на исполнение
chmod 674 public_executable_file   # 6 = rw- для владельца, 7 = rwx для группы
ls -l public_executable_file
```

> # -rw-rwxr-- ... public_executable_file

```bash
# Установить SGID на оба файла
chmod g+s *
ls -l
```

> # -rw-rwsr-- ... public_executable_file   (s маленькая)
> # -rw-r-Sr-- ... private_executable_file  (S большая)

#### 2.2.3. Поведение

- **public_executable_file**: SGID + `x` → любой пользователь при запуске получает права группы-владельца
    
- **private_executable_file**: SGID без `x` → файл нельзя запустить, SGID не имеет эффекта
    

#### 2.2.4. SGID на директориях (наследование группы)

```bash
mkdir shared
chmod g+s shared
```

Все файлы, созданные внутри `shared/`, будут принадлежать группе родительской директории, а не группе создателя.

### 2.3. Sticky Bit

**Назначение:** применяется к **директориям**. Защищает файлы внутри от удаления пользователями, которые не являются их владельцами.

#### 2.3.1. Установка и снятие Sticky Bit

```bash
chmod +t directory      # установить sticky bit
chmod -t directory      # снять sticky bit
```

#### 2.3.2. Отображение в `ls -ld`

```bash
chmod +t .
ls -ld .
```

> # drwxr-xr-t ... .   (t в конце прав)

#### 2.3.3. Поведение

- Владелец файла может удалить свой файл
    
- root может удалить любой файл
    
- Остальные пользователи не могут удалить чужие файлы (даже если имеют право `w` на директорию)
    

#### 2.3.4. Пример системной директории со Sticky Bit

```bash
ls -ld /tmp
```

> # drwxrwxrwt ... /tmp

Папка `/tmp` — общедоступная директория, где любой пользователь может создавать файлы, но удалять может только свои.

## 3. Сводная таблица специальных битов

| Название бита | Команда установки | Для файлов                       | Для директорий                       | Отображение                     |
| ------------- | ----------------- | -------------------------------- | ------------------------------------ | ------------------------------- |
| **SUID**      | `chmod u+s`       | Запуск от имени владельца        | Не применяется                       | `s`/`S` в позиции `x` владельца |
| **SGID**      | `chmod g+s`       | Запуск от имени группы-владельца | Наследование группы для новых файлов | `s`/`S` в позиции `x` группы    |
| **Sticky**    | `chmod +t`        | Не применяется                   | Защита от удаления чужих файлов      | `t`/`T` в позиции `x` остальных |

## 4. Права по умолчанию — `umask`

**`umask`** (user file-creation mode mask) определяет права доступа, которые будут установлены для вновь создаваемых файлов и директорий.

### 4.1. Просмотр текущей маски

```bash
umask
```

> # 0002

### 4.2. Установка новой маски

```bash
umask 333
```

### 4.3. Принцип работы

Права по умолчанию вычисляются как:

- **Для файлов:** `666` (rw-rw-rw-) минус `umask`
    
- **Для директорий:** `777` (rwxrwxrwx) минус `umask`
    

#### 4.3.1. Пример с umask 0002

```bash
umask 0002
touch file1
ls -l file1
```

> # -rw-rw-r-- ... file1   (664)

- Максимум: `666` → `110 110 110`
    
- Маска: `002` → `000 000 010`
    
- Результат: `110 110 100` → `rw-rw-r--`
    

#### 4.3.2. Пример с umask 333

```bash
umask 333
touch file2
ls -l file2
```

> # -r--r--r-- ... file2   (444)

- Максимум: `666` → `110 110 110`
    
- Маска: `333` → `011 011 011` (в восьмеричной)
    
- Результат: `100 100 100` → `r--r--r--`
    

### 4.4. Важные замечания

- **`umask`** действует только в рамках текущей сессии (терминала)
    
- После закрытия терминала маска сбрасывается к системному значению (обычно `002` или `022`)
    
- Системное значение по умолчанию можно изменить в конфигурационных файлах (`/etc/profile`, `~/.bashrc`)
    

### 4.5. Часто используемые значения umask

| umask | Права для файлов  | Права для директорий | Описание                            |
| ----- | ----------------- | -------------------- | ----------------------------------- |
| `002` | `664` (rw-rw-r--) | `775` (rwxrwxr-x)    | По умолчанию в многих дистрибутивах |
| `022` | `644` (rw-r--r--) | `755` (rwxr-xr-x)    | Стандарт для серверов               |
| `077` | `600` (rw-------) | `700` (rwx------)    | Максимально закрытый режим          |
## 5. Практические примеры

### 5.1. Работа со специальными битами

```bash
# Подготовка
touch some_file
chmod u+x some_file
```

### 5.2. Работа с Sticky Bit

```bash
mkdir shared_folder
chmod 777 shared_folder
chmod +t shared_folder
```

### 5.3. Работа с umask

```bash
umask 077
touch secret.txt
ls -l secret.txt         # -rw-------
```
